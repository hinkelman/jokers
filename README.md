# Jokers

A web version of Jokers, a marble-and-card board game for two teams of 2 or 3 players, so
family members can play together from different places. The full rules are in
[RULES.md](RULES.md).

Play at **https://jokers-hinkelman.fly.dev/**.

> **About the code:** Most of this code was written by Claude, an AI model from Anthropic, using
> Claude Code. No human has reviewed it. The rules in RULES.md come from the game as our family
> plays it. The exceptions are `lib/jokers/cards.ex`, `lib/jokers/colors.ex` and early versions
> of their tests, which were written by hand, and the Phoenix scaffolding generated by
> `mix phx.new`. Expect bugs, especially in rare rule situations, and check RULES.md if a move
> seems wrong.

## How to play

1. **Start a game.** On the home page, click **4 players** or **6 players**. This creates a game
   with a 6-character code, like `9ad18c`.
2. **Invite everyone.** Send the game page's link to the other players, or read out the code so
   they can enter it under **Join a game**.
3. **Pick your color.** Each color can be taken by only one person. Your browser remembers your
   seat, so you can reload the page or come back later and keep your color. Use **Leave seat**
   if you picked the wrong one. To play two colors from one device, open the second one in a
   private window or another browser.
4. **Take your turn.** Your side of the board is always at the bottom. Click a card in your hand,
   then choose a move:
   - Click a marble with a dashed orange ring to narrow down the moves. For a split 7 or 9, click
     the marble to move first, then the second. For a joker, click your marble, then the marble
     it lands on. Click any marble in your barn to bring one out.
   - Or pick a move from the list under your hand.

   The move is previewed on the board, with the marbles it changes ringed in orange. Click
   **Play this move** to play it, or **Cancel** to choose again.
5. **No playable cards?** The page tells you, and you pick a card to discard. Your 5th discard in
   a row brings a marble out.
6. **Winning.** When a team gets all its marbles home, the game ends. Click **Deal the next game**
   to play again; the deal passes to the left.

Every player's screen updates as soon as anyone moves.

Games are kept only in the server's memory. Restarting or redeploying the server ends every game
in progress.

## Running it locally

You need Elixir 1.14 or later (developed on Elixir 1.18 with Erlang/OTP 25). No database is needed.

```bash
mix setup
mix phx.server
```

Then visit [localhost:4000](http://localhost:4000). Run the tests with `mix test`.

## Code layout

- `lib/jokers/board.ex`: marble positions, and the legal moves for each card
- `lib/jokers/game.ex`: dealing, turns, discards and winning
- `lib/jokers/game_server.ex`: runs each game in its own process and keeps track of who holds each seat
- `lib/jokers_web/live/game_live/`: the lobby and game pages (Phoenix LiveView)
- `lib/jokers_web/components/board_components.ex`: draws the board and cards
- `lib/jokers_web/move_picker.ex`: choosing a move by clicking marbles

## Deploying

The app runs on [Fly.io](https://fly.io) as the app `jokers-hinkelman`, configured in
[fly.toml](fly.toml) to run one machine in Chicago (`ord`).

To deploy changes, run this from the repo:

```bash
fly deploy
```

Fly builds the image from the [Dockerfile](Dockerfile) on its own servers, so Docker isn't needed
locally.

Keep the app at **one machine**. Each machine keeps its own games in memory, so players on
different machines wouldn't see each other's games. `fly.toml` keeps that machine running at all
times, because stopping it would end every game.

### Setting it up from scratch

If the Fly app ever needs to be recreated:

1. Install flyctl and sign in:

   ```bash
   curl -L https://fly.io/install.sh | sh
   fly auth login
   ```

2. Create the app. If you choose a different name, update `app` and `PHX_HOST` in `fly.toml`.

   ```bash
   fly apps create jokers-hinkelman
   ```

3. Set the secret key Phoenix uses to sign cookies:

   ```bash
   fly secrets set --stage SECRET_KEY_BASE="$(mix phx.gen.secret)"
   ```

4. Deploy with high availability turned off, so Fly creates one machine instead of two:

   ```bash
   fly deploy --ha=false
   ```

Useful commands: `fly status` shows the machine, `fly logs` shows the server log, and `fly open`
opens the site.
